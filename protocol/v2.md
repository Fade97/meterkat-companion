# Relay protocol v2: client reference

For phone and companion implementers. The design and its reasoning are in [ADR 0001](../docs/adr/0001-relay-protocol-v2.md). Fixtures to test against: [`v2-test-vectors.json`](v2-test-vectors.json).

Hosted relay: `https://meterkat-relay.fabian-duerkop.de` (production, not yet deployed) and `https://meterkat-relay-staging.fabian-duerkop.de` (staging). The Node relay (`pnpm relay`) serves the same `/v2/*` routes next to `/v1/*`.

## Encoding

- JSON bodies, UTF-8. Responses carry `Cache-Control: no-store`.
- base64url without padding (RFC 4648 §5) for every binary value.
- Tokens are `"<sourceId>.<secret>"`: `sourceId` is 22 base64url chars (16 bytes), `secret` 43 chars (32 bytes). Send as `Authorization: Bearer <token>`.

## Crypto (Android API 26+, JCA only)

| Step | Primitive | JCA |
| --- | --- | --- |
| Key derivation | HKDF-SHA256, salt `"ai-usage/v2"`, info `"snapshot-aead|" + sourceId`, 32 bytes | `Mac.getInstance("HmacSHA256")`: extract `PRK = HMAC(salt, K)`, expand `T1 = HMAC(PRK, info ‖ 0x01)` (one block is 32 bytes) |
| Decryption | AES-256-GCM, 12-byte nonce, 128-bit tag appended to the ciphertext | `Cipher.getInstance("AES/GCM/NoPadding")`, `GCMParameterSpec(128, nonce)`, `updateAAD(ad)` |
| AAD | UTF-8 of `"ai-usage/v2|" + sourceId + "|" + epoch + "|" + seq + "|" + generatedAt` | |
| Plaintext | v1 snapshot JSON padded with trailing spaces to a multiple of 256 bytes | trim trailing spaces, then parse |
| Base64url | | `java.util.Base64.getUrlDecoder()` (API 26) or `android.util.Base64.URL_SAFE or NO_PADDING or NO_WRAP` |

`hkdf.okmHex` in the vectors is the derived AES key, so HKDF can be tested on its own.

## Pairing link

```
https://meterkat.fabian-duerkop.de/pair?v=2&relay=<origin>&source=<sourceId>&code=<code>#k=<base64url 32-byte key>&e=<epoch>
```

Accept a v2 link **only** from the in-app QR scanner or a verified App Link (`android:autoVerify="true"` intent filter for `https://meterkat.fabian-duerkop.de/pair` in package `de.fabianduerkop.meterkat`; that site hosts `/.well-known/assetlinks.json`). The in-app scanner is the fallback. Never register a custom scheme for v2: another app could claim it and receive the key.

Read `relay`, `source` and `code` from the query, and `k` and `e` from the fragment (`Uri.getFragment()`, parse as `key=value&…`). Reject the link if:

- origin + path is not exactly `https://meterkat.fabian-duerkop.de/pair`,
- `v` is not `2`,
- `relay` is not an `https://` origin (plain `http://` only for `localhost`, `127.0.0.1` or `[::1]` in debug builds; no path, query or credentials),
- `k` doesn't decode to 32 bytes, or `e` is not a positive integer.

`pairingLink.mustReject` in the vectors lists links that must fail. `aiusage://pair` is pilot-only legacy for v1 links (no `v`) and must never carry a v2 key.

Treat `source` as opaque (it embeds a relay MAC). Then:

```
POST /v2/pair {"sourceId": "...", "code": "..."}
→ 200 {"readerToken": "<sourceId>.<secret>", "deviceId": "..."}
→ 410 expired, used, or burned after 5 wrong guesses   → ask for a new QR
→ 409 device limit (10) reached
→ 429 too many attempts from this network
```

Store `readerToken`, `K`, `epoch`, `sourceId` and `relay` together in private storage. Keep `K` out of backups and logs.

## Reading

```
GET /v2/snapshot   (Bearer readerToken)
→ 200 {"v":2,"epoch":1,"seq":42,"generatedAt":…,"nonce":"…","ciphertext":"…"}
→ 204 no snapshot yet, or purged after 72 h without upload
→ 401 revoked or source deleted                     → show "disconnected", offer re-pair
```

Accept a 200 envelope only when all of these hold. Otherwise keep showing the previous data:

1. `epoch` equals the stored epoch. If greater: the key was rotated, so show "re-pair required". If smaller: ignore.
2. AES-GCM decryption with the AAD succeeds.
3. Inner `sequence` == `seq` and inner `generatedAt` == `generatedAt`.
4. `seq` > last accepted `seq` (persist it).
5. The inner snapshot passes the same validation as v1, and no provider's `sampledAt` is older than the last accepted one for that provider.

Age and "offline" come from `generatedAt` against the phone clock, as in v1.

## Leaving

```
DELETE /v2/device  (Bearer readerToken) → 200 {"ok":true}
```

Then delete the token and `K` locally.

## Writer routes (companion)

| Route | Result |
| --- | --- |
| `GET /v2/challenge` | `{challenge, bits, expiresAt}`; `403` if registration is closed |
| `POST /v2/sources {challenge, solution}` | `201 {sourceId, writerToken}`; `403` bad work/expired, `409` challenge used, `429` |
| `POST /v2/sources` with admin bearer | `201`, no proof of work |
| `POST /v2/pairing` | `201 {code, expiresAt}`; replaces any pending code |
| `PUT /v2/snapshot <envelope>` | `200`; `409` out of order, `429` faster than once per 20 s, `413` body > 16 KiB |

| `GET /v2/devices` | `{devices: [{id, pairedAt}]}` |
| `DELETE /v2/devices/<id>` | `{revoked: 0|1}` |
| `POST /v2/revoke` | revokes all phones and the pending code |
| `DELETE /v2/source` | `{deleted: true, devices: n}`; everything is gone |
| `DELETE /v2/sources/<id>` with admin bearer | operator deletion, `404` if unknown |

Any route can also return `429` (more than 120 requests per minute from one client address or IPv6 /64), `503` (relay misconfigured), or `500`.

Proof of work: find the smallest decimal string `solution` such that `SHA-256(UTF-8(challenge + "." + solution))` has at least `bits` leading zero bits.
